# 現場提案者辨識表

**用法**：10:00 聽社企的挑戰陳述時，手上拿這一張。
目標不是把對方塞進我們的框架，而是**快速判斷手上有沒有已驗證的證據可以用**。

> **現場優先原則（交接文件第 7 節）凌駕一切。**
> 現場出現的真實問題優先於任何預備方向。框架提供的是形狀與證據，不是答案。

## 第二步之二：被問到「已經有人做了」時

這題六個方向都會被問。**不要否認競品存在**，照這個順序答：

1. 承認它存在，講得比對方清楚（我們有完整競品表）
2. 說明競品證明了需求是真的——有人免費做、有人收費賣得掉、政府願意撥款
3. 說出我們**具體**不一樣的那一點，並標明那是賭注還是有證據
4. 答不出第 3 點就換方向。這是唯一該讓競品殺掉一個方向的時候

## 第三步：不屬於任何框架時 —— 用七格現場重建

多數情況會落在這裡。**不要慌，這才是現場優先原則預期的狀況。**
照順序問，問到第 3 格卡住就停下來——那代表問題還沒成形，不是我們該急著寫程式。

1. **誰、什麼時刻、什麼結果被卡住？**
   → 若答案是「所有人」「一直都是」，繼續追問到剩下一個人、一個時刻為止
2. **哪一步最花錢或最容易出事？**
   → 追問實際數字：幾小時、幾塊錢、多久一次
3. **⛔ 閘門：沒有 AI 的話，理想流程該長怎樣？**
   → **對方答不出來就停。** 這代表問題還沒被理解，硬上 AI 只會做出沒人用的東西
4. 這裡面哪一小塊可以交給**分類／檢索／抽取／摘要／建議／警告**其中一項？
   → 只能挑一項。挑不出來就是這題不適合做 AI
5. 哪個決定**絕對要人來下**？
6. 完整跑一次長怎樣？**出錯或不確定時長怎樣？**
7. 事後你們拿得走**哪一個數字**？

## 第四步：任何方向都要當場過的檢查

在決定投入之前，逐條確認。任何一條答不出來就換題。

- [ ] **競品**：有沒有現成或免費的產品做同一件事？（本專案已用這把尺刪掉 10 個方向）
- [ ] **死競品**：做過的人還活著嗎？——本輪撞到兩具屍體（Amplify、Yume Food）。
      **發現競品已死不等於發現空缺**，那是對 viability 的不利證據（見交接文件 §4.6）
- [ ] **社企定義**：服務對象真的是社會企業嗎？**受補助的慈善機構不算**
- [ ] **付費方**：誰出錢？若答案是「現金吃緊的小社企自己」，要重新設計
- [ ] **資料**：demo 用什麼？能不能誠實說明來源？**不得宣稱做過訪談、驗證或測試**
- [ ] **紅線**：有沒有滑向自動化福利／醫療／危機／資格判定，或個別員工評分監控？
